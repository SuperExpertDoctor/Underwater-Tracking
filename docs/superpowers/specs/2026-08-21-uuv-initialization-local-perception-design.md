# UUV 初始化、局部目标感知与移动航母战斗群设计

日期：2026-08-21  
状态：设计已确认，书面规格待复核  
范围：默认运行入口、UUV-only 任务执行、目标侧态势边界、区域交接、记忆输入与地图展示

## 1. 文档地位

本文是以下已确认设计的增补：

- `2026-08-19-uuv-only-carrier-region-mission-design.md`
- `2026-08-20-smart-assistant-memory-design.md`

发生冲突时，以本文为准。特别是，母舰返航目标不再是固定初始化坐标，而是沿既定航迹移动的航母战斗群会合槽位。

## 2. 目标

默认启动后应呈现一条真实的任务时序：

```text
航母战斗群按既定航迹航行
  -> 母舰携带各自 UUV 库存
  -> 方案选定最多 4 个执行区域
  -> 母舰离队并航行至区域外围
  -> 到达投放点后部署 UUV
  -> UUV 主动蛇形扫描
  -> 目标进入后被动协同跟踪
  -> 有效观测确认后完成区域交接
  -> 母舰回收 UUV
  -> 母舰与移动中的航母战斗群重新会合
```

同时满足以下约束：

1. 本算法没有 USV。实时仿真、规划、观测、编组、操作帧和 UI 均不创建或使用 USV。
2. 平台仅包括 1 艘航母、3 艘母舰和各母舰所属的 UUV。
3. UUV 初始状态为 `onboard`，到达投放点前不作为水下实体出现在地图上。
4. 目标仅感知自身附近有限区域，默认探测半径为 1200 m。
5. 目标侧 LLM 不得获得我方全局平台态势或我方传感器内部观测。
6. 普通物理 tick 和常规资源变化不触发 LLM 重规划；记忆处理保持异步。

## 3. 已确认的根因

### 3.1 默认入口仍使用旧世界

`main.py` 默认加载 `configs/scenario/default.yaml`。该场景走 legacy 初始化，把 12 台 UUV 直接设为 `deployed`，并按固定半径生成圆形队列；目标坐标与航母独立生成，因此初始空间关系不受任务语义约束。

### 3.2 舰载 UUV 被地图无条件绘制

操作帧包含母舰库存中的 UUV，Canvas 当前遍历全部 `frame.uuvs` 绘制实体、轨迹、命中区域和检测关系。即使 UUV 为 `onboard`，也会与母舰叠在一起显示。

### 3.3 目标侧输入泄漏全局态势

目标侧输入当前遍历全部 UUV/USV，计算平台距离、方位、声呐风险和通信关系；还把我方针对目标产生的被动观测反向提供给目标侧。这使目标实际获得的态势不受探测半径限制。

### 3.4 区域进入与交接判据偏弱

当前“进入概率”是目标估计均值是否位于区域内的 0/1 值。当前交接只要求下一组 UUV 已部署，没有要求健康状态、当前计划版本和有效被动观测。

### 3.5 记忆输入缺少稳定的周期态势摘要

MemoryWorker 已能异步读取事件、决策和当前方案，但周期环境态势主要依赖这些记录间接表达。需要增加低频、真值安全、可回溯的运行态势摘要，而不是把每个物理帧送入记忆 LLM。

## 4. 平台与航母战斗群

### 4.1 实时平台集合

新运行链路只允许：

```text
carrier_01: 航母，战斗群领舰
carrier_02: 母舰，固定 UUV 库存
carrier_03: 母舰，固定 UUV 库存
carrier_04: 母舰，固定 UUV 库存
uuv_00..uuv_11: 仅归属于三艘母舰
```

航母不拥有 UUV 库存，也不接收投放或回收任务。UUV 后勤归属在一次运行中不可跨母舰修改。

旧回放若包含 USV 字段，兼容适配器可以解析并丢弃这些字段，但不得把它们投影到新操作帧，也不得让它们进入任何算法决策。

### 4.2 移动战斗群

航母沿配置的确定性巡航航迹运动。三艘母舰各自拥有相对航母的编队槽位：

```text
slot_world(t) = carrier_position(t) + rotate(slot_offset, carrier_heading(t))
```

- 未出任务的母舰跟随各自槽位。
- 出任务的母舰脱离编队，按验证后的 A* 多站点路线执行投放和回收。
- 返航目标是预计到达时刻的移动槽位，而不是启动时的固定坐标。
- 每个观测边界根据战斗群当前位置和航迹更新会合预测；更新只能改变未完成返航段，不能使母舰瞬移或跳过已承诺停靠点。
- 母舰进入会合容差后恢复编队跟随状态，并产生一次 `carrier_returned_to_fleet` 事件。

航母速度和循环航迹继续使用环境配置中的 `speed_mps` 与 `patrol_route_xy`。每艘母舰通过 `formation_slot_offset_xy` 显式配置相对槽位，不从运行时位置反推。新增 `rendezvous_tolerance_m`，默认 250 m。返航 ETA 按母舰剩余已承诺航段、运动上限和航母循环航迹确定性迭代求解；无法在有限迭代内收敛时视为路线暂时不可行。

### 4.3 初始化空间关系

默认入口改为 UUV-only 显式场景。初始位置由配置确定，不再随机生成。

- 航母从配置航迹的起点出发，三艘母舰从各自相对编队槽位出发。
- 12 台 UUV 均为 `onboard`，内部位置跟随所属母舰。
- 目标初始位置位于预计任务走廊附近，距最近母舰约 2.5-4.0 km：在 UUV 被动声呐能力范围内，但在目标 1200 m 局部探测圈外。
- 使用相同配置和 seed 时，初始化结果逐字节一致。

## 5. UUV 可见性与投放时序

UUV 生命周期仍由 MissionController 管理：

```text
ONBOARD
  -> TRANSIT_TO_REGION
  -> ACTIVE_SCAN
  -> PASSIVE_TRACK / DEDICATED_TRACK
  -> RETURN_REQUIRED / RETURN_TO_REGION
  -> RECOVERING
  -> ONBOARD
```

任务模式和物理部署状态是两套不同字段。Canvas 可见性只以物理部署状态为准：

| 任务模式 | 典型物理部署状态 | 地图可见 |
| --- | --- | --- |
| `ONBOARD` / 舰载 `TRANSIT_TO_REGION` | `onboard` | 否 |
| `ACTIVE_SCAN` / `PASSIVE_TRACK` / `DEDICATED_TRACK` | `deployed` | 是 |
| `RETURN_REQUIRED` / `RETURN_TO_REGION` / `RECOVERING` | `returning` 或 `deployed` | 是 |
| 已回收 | `onboard` | 否 |

故障状态不单独决定可见性：仍在水中的故障 UUV 保持可见，完成回收后才从地图移除。

地图展示规则：

- `onboard` UUV 不绘制实体、标签、轨迹、选择命中区域、通信线或目标检测关系。
- 母舰库存面板继续列出 `onboard` UUV 及其健康、能量和所属母舰。
- 母舰到达区域外围投放点并产生 `uuv_deployed` 后，UUV 从母舰当前位置进入地图。
- 多台 UUV 使用各自的蛇形覆盖航迹，不生成固定圆形编队。
- `returning` UUV 保持可见，并显示到所属母舰的回收关系。
- 回收完成转为 `onboard` 后，UUV 从地图移除并回到库存面板。

## 6. 目标局部感知边界

### 6.1 单一探测范围来源

目标探测范围由场景中的潜艇配置提供，默认值为 1200 m。后端检测事件、目标侧证据构建、操作帧和前端探测圈必须使用同一个值；前端不得用更大的常量扩张实际感知范围。

### 6.2 目标侧平台白名单

每个观测边界先在传感器边界建立目标本地白名单：

```text
local_platform_ids = {
  platform_id
  | platform is physically exposed
  and private_world_distance(target, platform) <= detection_range_m
}
```

`physically exposed` 包括航母、母舰，以及处于 `deployed`、`returning` 或仍在水中的故障 UUV；不包括 `onboard` UUV。仿真传感器边界可以像其他传感器模型一样使用私有世界坐标判定是否发生探测，但私有坐标不得离开该边界。探测成功后只生成带确定性种子噪声的目标侧距离、方位和平台类别估计。

目标侧 `platform_threats`、活动发射源、通信暴露和触发证据只能引用该白名单及其带噪局部估计。LLM 输入不得包含用于门控的私有距离或坐标。

检测事件使用滞回避免边界抖动：默认在配置半径内进入，超过 `detection_range_m + 100 m` 才离开。同一 `(target_id, platform_id)` 感知 episode 只产生一次进入和一次离开事件。

### 6.3 禁止反向泄漏我方观测

我方 UUV 生成的被动测向属于我方内部观测，不能反向成为目标侧 `AdversaryObservation`。目标侧只允许使用：

- 自身运动与意图信念；
- 局部白名单内平台的目标侧估计方位、距离和威胁等级；
- 1200 m 范围内实际听到的主动发射；
- 自身此前决策历史；
- 由上述局部证据产生的检测进入、检测离开和暴露事件。

目标侧输入和输出继续禁止真值字段。目标侧 LLM 没有局部新证据时不应因为远处平台活动而运行。

## 7. 区域进入与交接

### 7.1 概率进入判据

区域进入概率使用当前目标二维估计分布及其协方差，计算落入任务区域多边形的概率质量。对于当前轴对齐方形区域，使用确定性的二维高斯矩形积分；可执行计划继续拒绝非轴对齐区域。非有限或非正定协方差不得参与积分，结果限制在 `[0, 1]`。

只有当概率达到 `scenario.region_entry_probability_threshold`（默认 0.70），并连续满足 `scenario.region_transition_confirm_cycles`（默认 2）个 `timing.observation_step_s` 观测边界后，区域才从 `ACTIVE_SCAN` 转为 `PASSIVE_TRACK`。计算不得读取目标真值。

### 7.2 有效交接判据

旧区域进入 `HANDOFF_PENDING` 后，只有同时满足以下条件才产生 `handoff_completed`：

1. 下一任务区域和交接引用属于当前 MissionController 计划版本。
2. 下一组要求的 UUV 已部署且健康，未处于返航、故障或资源耗尽状态。
3. 下一组已切换为被动模式。
4. 当前观测周期至少有 `group_min_size` 个不同的下一组 UUV 产生通过门限的有效被动观测。
5. 下一组群组报告未触发硬保护条件。

交接完成前，旧区域保持被动跟踪，不生成回收任务。交接完成后，旧区域转为 `TRACKING_COMPLETED`，其普通任务 UUV 才进入回收链路。专属跟踪 UUV 不因普通区域交接自动解除。

这里的“有效被动观测”指当前观测边界内，由下一组成员生成、通过量测门控、进入该组 `GroupReport.belief.source_observation_ids` 的被动 BearingObservation；按不同 `observer_id` 计数。“健康”指 MissionController 的资源状态同时满足 `healthy`、`capability_active`、能量高于下限、里程低于上限，且任务模式不属于返航或故障状态。“下一组要求的 UUV”取当前计划版本 RegionMissionState 的主动扫描与被动跟踪成员并集。

若下一组在预计交接窗内永久不可用，或旧组先达到资源边界，区域进入 `DEGRADED`，产生带来源 ID 的 `handoff_blocked` 方案影响候选事件；在新计划提交前不伪造 `handoff_completed`。

## 8. 任务与资源轮转

已实现的两类轮转继续保留：

- 任务轮转：目标沿区域链移动并完成有效观测交接。
- 资源轮转：里程、能量、健康或能力达到边界后退出任务并触发回收或专属返回区域。

累计里程包含投放后的全部水下运动，包括进入区域、扫描、跟踪、返回区域和前往回收点。普通 UUV 达到资源边界后进入 `RETURN_REQUIRED`；专属 UUV 先进入 `RETURN_TO_REGION`，到达所属区域后清除专属锁定并恢复普通模式。

## 9. 记忆与 LLM 事件边界

### 9.1 保留现有异步架构

MemoryWorker 继续独立于物理 tick 运行。短期压缩、长期筛选、提炼、向量化、版本更新、衰减和归档均不得阻塞 SimulationEngine 或 MissionController。

### 9.2 周期态势摘要

在仿真时钟每个 `timing.progress_report_s` 边界持久化一条 `periodic_situation_summary` 真值安全事件，至少包含：

- 当前 plan version；
- 区域生命周期与覆盖状态；
- 航母与母舰任务状态、库存计数和返航状态；
- UUV 模式、部署状态、能量、里程和健康状态变化摘要；
- 目标公开估计质量、意图和预测变化摘要；
- 本周期关键来源事件 ID。

摘要进入 EventRepository 后由 MemorySourceReader 和 MemoryWorker 使用游标异步读取。每个物理帧不直接调用记忆 LLM。

事件 ID 使用 `periodic_situation_summary:{scenario_id}:{sim_time_s}`，相同场景和仿真时刻重复提交时保持幂等。摘要只包含操作帧允许公开的估计和状态，不包含目标真值、私有传感器门控坐标或模型私有推理。MemorySourceReader 仅在工作项成功持久化后推进来源游标；重启后从最后已提交游标继续读取。

### 9.3 重规划边界

常规观测、周期摘要、正常投放、正常回收、主动 ping 和普通资源状态更新默认只进入审计与记忆。现有 `evaluate_plan_impact` 使用当前计划版本、活动目标/区域/UUV、质量门限、资源、通信和时间窗可行性评估事件；`EventEpisodeGate` 负责进入、恢复、升级和去重。只有 `plan_impact=true` 的关键事件批次才进入 LLM 重规划链路，过期计划版本产生的批次不得覆盖当前方案。

## 10. UI 行为

保留现有智能助理、记忆窗口、LLM 思考过程和 Memory Steam：

- 智能助理方案调整仍为预览、版本校验、专家确认、应用。
- 证据回溯继续验证记忆携带的事件、决策、知识和方案来源。
- `LLM 思考过程` 只展示面向操作员的方案原因，不展示私有 chain-of-thought。
- `Memory Steam` 继续通过 cursor 增量读取后台事件。
- 初始地图只展示航母、三艘母舰、目标公开估计和规划区域；UUV 投放后才出现。

## 11. 错误与降级

- 目标侧输入若包含局部白名单外平台，拒绝构建该输入并记录边界错误。
- 概率积分失败时保持上一生命周期，不允许回退到真值或直接切换被动模式。
- 交接证据不足时保持 `HANDOFF_PENDING`，旧组继续工作。
- 移动会合路线暂时不可行时，母舰保持当前安全航段并触发确定性重规划，不直接驶向旧固定坐标。
- MemoryWorker、嵌入模型或记忆 LLM 不可用时明确降级，但物理任务继续执行。
- LLM 不可用时沿用上一版已验证方案，不伪造新方案。

## 12. 验收测试

实现按测试驱动方式完成，至少覆盖：

### 初始化与地图

- 默认入口加载 UUV-only 场景。
- 初始固定 1 艘航母、3 艘母舰、12 台 onboard UUV，不存在 USV。
- 初始帧不绘制 onboard UUV，也不产生 UUV 轨迹和命中区域。
- 投放事件发生后 UUV 才进入地图，且不形成圆形队列。

### 移动战斗群

- 航母按配置航迹确定性移动。
- 待命母舰保持编队槽位。
- 任务母舰离队、完成停靠点并返回移动槽位。
- 两次航次各自产生一次返队事件。

### 目标局部感知

- 1200 m 外平台不进入目标检测列表、威胁摘要、活动发射源或通信暴露。
- 航母、母舰和水中 UUV 只有进入配置探测范围后才被目标感知；`onboard` UUV 不作为独立平台出现。
- 我方被动测向不进入目标侧观察列表。
- 默认场景的平台越过 1200 m 进入边界和 1300 m 离开边界时，每个 episode 只产生一次对应事件。
- 前端探测圈与后端配置值一致；非默认场景测试跟随其配置值，不硬编码 1200 m。

### 区域状态机

- 概率质量连续达到阈值后才切换被动模式。
- 部署、健康、被动模式或当前计划版本任一条件不满足时不得交接。
- 没有足够有效被动观测时保持 `HANDOFF_PENDING`。
- 下一组硬保护失败时不得交接；交接窗内不可用时进入 `DEGRADED` 并产生 `handoff_blocked`。
- 有效观测满足后先激活下一组，再完成旧组回收。

### 记忆与 UI

- 周期态势摘要持久化并由 MemoryWorker 游标读取。
- 周期摘要不包含目标真值，重复提交幂等，重启后从已提交游标继续。
- MemoryWorker 降级或超时不阻塞物理 tick。
- 周期摘要不触发 LLM 重规划。
- 关键方案影响事件仍可触发方案调整。
- 智能助理、Memory Window、Memory Steam 和 LLM 思考标签继续通过现有测试。

### 边界与降级

- 新实时操作帧和所有规划输入均无 USV；旧回放 USV 字段在适配边界被丢弃。
- 回收完成后 UUV 从地图实体、轨迹、命中检测和通信关系中移除。
- 动态返航段更新不产生位置跳变，也不删除已承诺停靠点。
- 目标侧输入不包含白名单外 ID 或私有门控坐标。
- 概率积分失败、会合路线不可行、LLM 不可用和记忆服务降级均遵守第 11 节行为。

## 13. 非目标

- 不增加 USV 或 USV 兼容决策路径。
- 不在本次工作中扩展多目标资源竞争优化。
- 不展示或存储模型私有 chain-of-thought。
- 不把目标探测改成全局共享真值。
- 不重写现有已通过测试的记忆版本库和智能助理 UI。
