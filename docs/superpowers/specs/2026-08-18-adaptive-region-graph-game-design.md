# 自适应目标区域编组、知识图谱与敌我博弈展示设计

**日期：** 2026-08-18
**状态：** 已完成设计确认，待实现计划
**范围：** `/home/shuixia/users/houguoqiang/projects/Underwater-Tracking`

## 1. 背景与目标

当前系统已经具备目标意图理解、轨迹预测、分段跟踪和敌方决策的后端模型，但操作界面仍以普通列表和静态方案信息为主：

- `TargetRegionPlan / RegionCell / RegionTask` 没有进入 `OperationalFrame`，前端无法展示真实的预测子区域及其任务关系；
- UUV/USV 编组在界面上容易被理解为人为固定指派，而目标需求是由 LLM 根据目标预测域自主形成编组；
- 右侧“方案约束”不能反映任务组是否完成跟踪，也不是人类专家反馈的主要载体；
- 地图上的红色大虚线圆是探测范围，却与预测区域视觉混淆；
- 当前目标轨迹和仿真响应需要更平滑、更能体现“我方跟踪—敌方规避—我方再规划”的闭环。

本设计以单个目标 `target_01` 为主场景，完成以下目标：

1. 以目标预测走廊为中心生成/展示更细粒度的子区域；
2. 允许 LLM 自主决定每个子区域的 UUV/USV 编组，不施加固定数量限制；
3. 通过知识图谱表达“区域时间顺序、实体负责关系和任务效果”；
4. 将右侧面板改为可折叠功能卡，并用人类专家反馈驱动下一轮方案调整；
5. 默认隐藏探测范围，只在图层开关打开时显示；
6. 让目标与跟踪方使用平滑轨迹和动态响应，体现敌我博弈。

## 2. 已确认的设计决策

### 2.1 区域与网格

- 地图保留一个更细的全局参考网格，默认从当前约 8 等分提高到 16×16 参考网格；
- 目标预测走廊内部使用自适应子区域，子区域数量来自区域计划，不绑定 UUV/USV 数量；
- 一个区域对应一个 `RegionTask`，区域按 `predecessor/successor` 或时间窗形成有向接力链；
- 只展示一个目标的区域链路，但数据结构保留 `target_id`，以便后续扩展多目标。

### 2.2 LLM 自主编组

- LLM 根据预测域、意图、通信关系、平台状态和历史跟踪效果自主选择 `assigned_uuv_ids` 与 `assigned_usv_ids`；
- 不再以固定的 UUV/USV 数量作为策略层限制；一个区域可以由任意数量的 UUV/USV 组成，也可以在资源不足时进入 `uncovered/degraded` 状态；
- 系统仍保留底层安全校验：平台 ID 必须存在、不能重复、通信链路和运动能力不能被伪造，避免“无约束”被误解为绕过物理安全；
- `required_uuv_count / required_usv_count` 不再作为默认策略门槛，而作为 LLM 方案的可解释结果或需求建议；若没有成员，界面明确显示未覆盖，不隐式补齐虚假编组。

### 2.3 跟踪效果与专家反馈

- 移除右侧操作界面的“方案约束”展示；
- 跟踪效果以每个 task group/region task 为中心展示：质量分数、估计 RMSE、覆盖时长、接力完成度、通信状态、趋势和降级原因；
- 人类专家通过自然语言反馈区域效果、优先级或接力偏好，反馈作为下一轮 LLM 决策的软输入；
- 反馈应被记录在决策链中，并能在回放/时间线中看到“反馈 → 重新预测 → 编组调整 → 效果变化”。

### 2.4 轨迹与探测图层

- 目标历史轨迹使用平滑折线/样条曲线显示；目标预测轨迹显示中心线和不确定性走廊；
- 敌方目标根据我方暴露程度、探测风险和当前编组采取变向、规避、逃逸或诱饵策略；
- 我方在预测域或任务效果明显变化时重新计算接力区域与编组；
- 红色虚线探测范围默认关闭，作为独立的 `detection-range` 图层开关，不再作为预测区域绘制；
- 预测走廊、细分子区域、实体—区域关系、我方轨迹、敌方轨迹、探测范围均为独立图层。

## 3. 数据契约设计

### 3.1 后端区域视图

在 `domain.ui_models` 增加面向界面的只读视图模型，避免把内部 Pydantic 规划模型直接暴露给前端：

```text
RegionCellView
  region_id, target_id
  grid_x, grid_y
  min_x, max_x, min_y, max_y
  center_xy, cell_size_m
  first_entry_s, last_exit_s
  occupancy_likelihood, intent_labels
  predecessor_region_ids, successor_region_ids

RegionTaskView
  region_id, target_id
  active_window, visit_window_index
  assigned_uuv_ids, assigned_usv_ids
  assignment_status
  communication_links
  tracking_effect
  degraded_reasons

TrackingEffectView
  quality_score, estimated_rmse_m
  coverage_fraction, handoff_completion
  communication_health, trend
  status, explanation

TargetRegionPlanView
  target_id, prediction_id, intent_label, intent_confidence
  cell_size_m, cells, tasks, plan_revision
  fallback_used, fallback_reason
```

`OperationalFrame` 增加 `regional_plans` 字段，默认空元组以保持旧帧和回放兼容。`frame_builder` 从 `TrackingPlan.regional_plans / region_tasks` 生成视图，并将实时任务效果合并进去。

### 3.2 图谱关系

前端知识图谱不依赖后端额外存储一份图结构，而由区域视图稳定推导：

- `region_i -> region_j`：来自 successor/predecessor 或时间窗排序，表示目标可能的时间顺序；
- `UUV/USV -> region_i`：来自 `assigned_uuv_ids / assigned_usv_ids`，表示责任关系；
- region 节点颜色：按 task status 和 tracking effect；
- entity 节点颜色：按通信、健康、传感器和当前任务状态；
- 连线颜色：接力顺序使用琥珀色，责任关系使用青绿色，失联/降级使用红色或灰色；
- 节点点击只改变详情卡和高亮，不改变 LLM 的自主决策。

## 4. 前端交互与布局

### 4.1 主地图

- `CanvasMap` 默认绘制 16×16 参考网格；
- 从 `regional_plans` 绘制目标预测域的子区域边界、`region_id`、时间窗和覆盖质量；
- 预测域使用紫色半透明走廊；区域任务用淡色填充，当前执行区域使用琥珀色，已完成使用灰绿色，降级使用红色；
- 目标探测范围由 `showDetectionRange` 控制，默认 `false`；
- 目标轨迹和 UUV/USV 轨迹保持独立开关，避免视觉层叠。

### 4.2 右侧可折叠卡片

按默认优先级排列以下卡片，每张卡独立展开/收起并保留状态：

1. **态势概览**：仿真时间、目标、当前预测质量、活动区域数；
2. **区域任务知识图谱**：SVG 图谱，方形 region、圆形 UUV/USV、箭头接力和任务效果；
3. **敌方机动 / 我方响应**：当前敌方意图、规避动作、发现我方实体数、我方重规划时间和响应状态；
4. **跟踪效果 / 专家反馈**：task group 效果列表、趋势、自然语言反馈输入和提交结果；
5. **平台状态**：UUV、USV 和通信链路；
6. **回放与图层**：时间轴以及预测域、子区域、任务关系、轨迹、探测范围开关。

原“方案约束”卡片不再作为操作面板展示。底层安全校验只在任务状态、降级原因或反馈结果中以必要信息体现。

### 4.3 知识图谱实现

使用 React + SVG 实现，不引入重量级图数据库或图形库：

- 节点位置由区域时间轴和实体簇确定性计算；
- 支持缩放、拖拽、节点点击、高亮邻接关系；
- 节点与边使用可访问的 `aria-label`，并在窄屏下允许横向滚动；
- 任务效果更新只更新颜色、标签和边状态，不破坏用户当前展开/选中状态。

## 5. 敌我博弈仿真设计

### 5.1 敌方

- 保持现有 `AdversaryEscapeDecision` / `apply_adversary_decision` 接口；
- 将敌方动作从单点方向调整为平滑的曲率/转向率受限轨迹；
- 决策输入包括当前目标意图、预测走廊、被探测平台、通信暴露、最近一次接力区域和历史规避动作；
- 动作至少覆盖保持航向、机动规避、诱导/假目标、加速逃逸和撤离，动作切换具有冷却时间，避免每步抖动。

### 5.2 我方

- 在目标预测域变化、跟踪效果下降、通信状态变化或敌方动作变化时触发快速重规划；
- LLM 输出区域任务及任意规模的 UUV/USV 编组，确定性验证器负责可执行性；
- 平台沿区域中心/拦截点平滑移动，并根据下一子区域的时间窗提前接力；
- 每次重规划记录触发事件、旧区域任务、新区域任务、响应延迟和效果变化。

### 5.3 不可用服务与降级

如果 LLM/知识服务暂时不可用：

- 不伪造 LLM 已完成的编组决策；
- 保留上一版已验证任务并标记 `degraded`；
- 图谱显示“决策暂停/等待反馈”，记录原因；
- 回放仍可展示历史真实帧。

## 7. 验收标准

- 地图默认看不到红色探测范围；打开图层后才显示；
- 全局网格明显比当前更细，且不遮挡预测域和任务图层；
- 单个目标存在可排序的多个 region 节点，region 节点之间有时间方向；
- 每个区域可显示任意数量的 UUV/USV 责任实体，不因固定数量不足而伪造成员；
- 右侧所有主要功能均可折叠；
- 知识图谱能动态反映 LLM 编组变化、接力状态和跟踪效果；
- 人类专家反馈能被提交、记录并进入下一轮决策输入；
- 敌我轨迹平滑且能体现至少一次“敌方规避 → 我方重规划 → 区域接力/效果变化”；
- LLM 服务不可用时界面明确显示降级，不冒充自主决策成功；
- 旧回放帧仍能读取，新增字段缺失时使用空默认值。

## 8. 风险与取舍

- 真实区域计划没有进入旧 `OperationalFrame`，因此阶段 1 必须先于知识图谱，不能只做前端假数据；
- “不施加限制”不能删除物理和通信安全校验，否则图谱会展示不可执行任务；本设计将策略约束与安全约束分离；
- 敌我博弈需要稳定的决策节流和轨迹平滑，否则会出现高频抖动；
- 右侧图谱节点较多时需要限制显示范围和支持局部聚焦，默认只展示当前目标的区域链。
