# 长时闭环运行与 100x 回放验收设计

日期：2026-08-20  
状态：设计已确认，待实施  
范围：Underwater-Tracking

## 1. 目标

在不改变“仿真时间”和“演示时间”含义的前提下，形成可持续运行的生产闭环：

```text
仿真时钟推进 0s -> 28800s
  -> 观测、估计、编组、任务规划和资源轮换
  -> 事件账本与操作帧
  -> 真实回放 API 分页读取全部帧
  -> UI 以 1x/4x/10x/.../100x 播放到末帧
```

本次验收的仿真时长固定为 8 小时，即 `28800s`。100x 是回放播放倍率，不是缩短仿真时钟，也不改变后端事件的仿真时间戳。以当前 5 秒物理步长为例，完整回放应包含从 `0s` 到 `28800s` 的全部 5760 个步进帧（实际数量以运行时帧合同为准，但必须覆盖完整时间范围）。

## 2. 当前问题与设计结论

### 2.1 物理角度必须满足半开区间

所有航向角统一使用 `[-pi, pi)`。浮点计算在 `-pi` 附近可能把结果舍入到正 `pi`，导致操作帧校验在长时间运行后失败。运动学归一化函数必须对边界做显式收敛，任何写入操作帧的航向都必须满足严格的半开区间约束。

### 2.2 无观测周期仍然推进估计时钟

空观测不是停钟。每个编组周期必须接收当前仿真时间，即使本周期没有有效测向。估计器在空观测周期执行预测，报告时间推进到当前周期；最后一次有效观测时间单独保留，用于计算数据新鲜度和质量衰减。

### 2.3 物理执行计划必须覆盖全部母舰

UUV-only 物理执行的载体集合是运行时的完整母舰集合。计划中的 `carrier_missions` 必须与物理母舰 ID 集合相等，缺少母舰、额外母舰或不一致的任务键都必须在验证或应用前拒绝，避免部分安装计划造成资源状态与计划状态分裂。

### 2.4 UI 状态只反映当前周期

实时状态投影不能用历史事件冒充当前周期事件。历史事件仍可用于事件时间线，但 `LLM thinking`、当前阶段和当前触发原因必须只由当前周期事件及当前计划状态派生；没有当前周期事件时显示稳定的周期性评估状态，而不是重复上一次旧触发。

### 2.5 回放必须读取真实后端全量数据

前端不能依靠 mock 数据或单页截断来验证回放。回放 API 保持分页合同，前端按 `total_count` 连续读取指定范围的全部页，去重后按仿真时间排序。客户端保留明确的上限以保护浏览器内存，但上限必须覆盖 8 小时验收所需的全部帧；无法完整加载时必须暴露错误，不能静默显示残缺回放。

### 2.6 播放倍率只影响演示计时

播放控制提供 `1x`、`4x`、`10x`、`20x`、`50x` 和 `100x` 等选项。倍率只影响相邻仿真帧之间的 wall-clock 延时，不改写帧中的 `sim_time_s`，也不影响实时模式、后端仿真推进或事件排序。播放延时按相邻帧仿真时间差计算，避免固定间隔在变步长或稀疏帧时产生速度漂移。

## 3. 方案架构

### 3.1 后端数据流

```text
SimulationEngine
  -> wrap_angle 严格归一化
  -> GroupManager.invoke(sim_time_s=当前仿真时刻)
  -> 空观测周期预测到当前时刻
  -> MissionController / optimizer 验证完整母舰计划
  -> 当前周期事件、计划版本、资源状态
  -> OperationalFrameBuilder
  -> ReplayWriter / ReplayService
```

每个操作帧必须满足：

- `sim_time_s` 单调不下降，且属于 `[0, 28800]` 验收范围；
- 所有 UUV 航向满足 `[-pi, pi)`；
- 编组报告时间不落后于当前周期时间（有效观测时间字段除外）；
- 计划中的母舰任务集合与活跃母舰集合一致；
- 事件的仿真时间不晚于生成该帧的仿真时刻；
- 无观测周期仍有质量年龄增长和预测状态，不复制旧报告作为新报告。

### 3.2 回放数据流

```text
GET /api/replay?start_s=0&end_s=28800&offset=0&limit=N
  -> total_count
  -> offset += returned_count
  -> 直到 offset >= total_count
  -> merge/dedupe/sort
  -> PlaybackBar 选择倍率
  -> 相邻帧时间差 / playbackRate
  -> 播放到最后一帧并停止
```

UI 的完整性检查至少包括：

- 首帧和末帧仿真时间覆盖 `0s` 和 `28800s`；
- 加载帧数量等于后端 `total_count`（在客户端上限内）；
- 100x 播放最终索引等于最后一帧，且自动停止；
- 网络、分页或数据校验失败时展示可读错误并停止播放；
- 业务数据全部来自当前后端接口，不保留用于“通过测试”的业务 mock。

## 4. 修改边界

后端改动集中在运动学边界、编组时钟、任务计划验证和实时状态投影；不删除仍被生产链路使用的 IMM/UIF、任务优化器、事件账本或回放索引。前端改动集中在真实回放分页、播放倍率和相邻帧计时；不改变实时 WebSocket 数据合同。

新增测试覆盖：

1. 角度边界回归；
2. 空观测周期的预测与新鲜度；
3. 缺失或额外母舰计划拒绝；
4. 历史事件不污染当前周期状态；
5. 回放分页合并、去重和完整加载；
6. 倍率选项和变步长播放计时；
7. 确定性 8 小时后端运行、真实回放 API 和 100x 浏览器回放验收。

## 5. 验收标准

验收必须在合并后的 `master` 上完成，且工作区最终停留在 `master`：

- 使用确定性 LLM/策略适配器，完整推进仿真 `28800s`，不以提前停止替代长时验收；
- 运行期间至少产生计划生成、任务调整、目标/区域事件、UUV 能力或里程变化、母舰投放/回收及资源轮换相关数据；
- 全量操作帧通过 schema 和跨帧一致性检查，无正 `pi` 航向、倒退报告时间或残缺母舰计划；
- `/api/replay` 分页返回的总帧数和时间范围与生成数据一致；
- UI 连接真实后端，加载完整 8 小时回放，切换 `100x` 后播放到 `28800s` 末帧并自然停止；
- 后端、前端单元测试、集成测试和浏览器验收均记录实际命令与结果；若外部真实 LLM 依赖不可用，必须明确标记为外部依赖，不得用 mock 结果冒充通过。
