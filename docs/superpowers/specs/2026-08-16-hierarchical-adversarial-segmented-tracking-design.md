# 分层对抗式单目标分段跟踪总体设计

## 1. 目标与设计原则

本设计重构现有仅以 UUV 为主体的跟踪算法，形成“母舰主脑 + USV 水面节点 + UUV 水下节点 + 敌方潜艇脑”的单目标对抗式稳定跟踪系统。

系统必须根据预定作战规则、战场观测、平台能力和资源状态，预测目标可能前往的水域，将预测航路划分为空间分段，动态形成混合跟踪编组，提前预置后续编组，并通过重叠观测完成接力交接。目标潜艇根据自身的部分可观测态势制定逃逸方案，双方在独立认知基础上持续博弈。

核心原则如下：

- 真实 LLM 是母舰主脑、UUV 从脑和敌方潜艇脑的在线决策核心，不允许规则策略、mock 模型或启发式策略替代在线语义决策。
- 确定性算法负责数值计算、候选生成、运动学编译、约束校验和命令执行，不能越权替代 LLM 选择战略或战术构想。
- 仿真真值、我方认知和敌方认知严格隔离；任何 LLM 都只能读取本方可观测信息。
- 轮转不是独立的低电量修补逻辑，而是预定分段跟踪方案的一部分。
- 战略方案由人在环路确认；从脑只在已批准规则边界内自治。
- 采用契约先行、分层替换方式迁移现有系统，不原地扩大旧单体模型。

## 2. 已确认范围

### 2.1 首轮范围

- 单一水下潜艇目标。
- 1 艘母舰、4 艘 USV、12 艘 UUV。
- USV 和 UUV 均由母舰携带、投放和回收。
- USV 受母舰最大保障半径硬约束。
- USV 组成水面通信 mesh，并为 UUV 与母舰主脑提供中继。
- USV 和 UUV 组成面向同一目标的混合 `TrackingTaskGroup`。
- 使用二维平面运动学，不建模深度和完整三维动力学。
- 使用协同多基地主动声纳和持续被动声纳。
- 使用空间分段、提前预置、重叠观测和显式交接。
- 主脑、从脑和敌方脑使用三个独立真实 LLM 角色配置。
- UI 参考本地 `/home/shuixia/users/houguoqiang/projects/Maritime-Surveillance/` 的布局和风格。

### 2.2 首轮不包含

- 多目标资源竞争。
- 声学诱饵、假目标实体和多假设数据关联。
- 水声链路带宽、时延、丢包和消息队列仿真。
- 三维深度机动或六自由度动力学。
- 规则策略或 mock LLM 对在线真实 LLM 的运行时接管。

mock LLM 只用于自动化测试中的可重复 graph 回归；真实 LLM 端到端验收必须通过。

## 3. 实施分解

总体重构拆成四个连续子项目，每个子项目在实施前拥有独立规格和计划：

1. **战场与平台核心**：统一平台状态、配置、二维运动学、距离通信图、传感器和观测边界。
2. **混合编组与主从脑**：空间分段、动态编组、接力交接、母舰主脑、group 从脑、声纳模式决策和人在环路。
3. **敌方对抗建模**：敌方 belief、潜艇 LLM、逃逸构想、确定性航迹编译和双方时序隔离。
4. **UI 与真实 LLM 验收**：指挥界面、审计、回放、指标、真实模型运行和端到端验收。

子项目按顺序实施，不并行修改共享领域契约。

## 4. 总体架构

系统分为五层：

### 4.1 战场仿真层

保存母舰、USV、UUV 和潜艇的真实二维状态，负责：

- 位置、航向、速度、加速度和转向率推进；
- 平台能源与投放、回收状态；
- 声纳观测生成；
- 距离连通计算；
- 潜艇真实任务和真实逃逸航迹；
- 独立评估真值输出。

真值不得进入 operational snapshot、LLM prompt、决策台账或普通 UI frame。

### 4.2 双方认知层

- 每个混合 group 维护局部 `TargetBelief`。
- 母舰主脑维护由当前连通 group 报告融合得到的 `GlobalTrackingBelief`。
- 断联 group 的报告保留来源时间并随时间标记为陈旧，不伪装成实时信息。
- 潜艇维护 `EnemyBeliefState`，只消费自身能够感知的主动脉冲和概率性平台噪声接触。

### 4.3 分层智能决策层

- `CarrierMasterGraph`：全局意图识别、预测、分段、编组、投放回收、方案审批与版本提交。
- `GroupSlaveGraph`：局部观测、声纳模式、局部队形、交接执行和断联自治。
- `AdversaryGraph`：威胁评估、逃逸构想和目标任务权衡。

三个 LLM 角色在业务语义上分别部署于母舰、group 主 UUV 和潜艇本体。战场通信图只控制脑与脑之间能够交换哪些态势和指令，不控制各角色调用自身 LLM 的能力。仿真实现可以通过同一外部模型服务承载三个角色，但必须保持独立线程、上下文、配置和审计记录；模型服务传输失败按第 15 节暂停整个仿真。

### 4.4 确定性算法层

提供通信图、滤波融合、预测、空间分段、截获点、动态编组、候选航迹、运动控制和独立校验器。该层不调用 LLM，也不选择语义策略。

### 4.5 指挥界面层

通过 FastAPI、WebSocket、JSONL 和 React Canvas 持续展示实时/回放态势、方案审批、事件、LLM 审计和指标。

## 5. 平台与能力契约

使用公共平台标识和类型化状态，避免继续把所有资源塞入 `UUVState`。

### 5.1 `CarrierState`

关键字段：

- `carrier_id`、位置、航向、速度；
- `support_radius_m`；
- USV/UUV 在舰、投放、在外、返航和回收清单；
- 投放/回收作业状态与当前队列；
- 可用投放/回收能力。

### 5.2 `USVState`

关键字段：

- 二维运动、能源和部署状态；
- 水面通信半径、水下通信半径；
- 主动发射、主动接收和被动接收能力；
- 与母舰距离、所属 group 和当前任务；
- 主动声纳模式和冷却状态。

### 5.3 `UUVState`

关键字段：

- 二维运动、能源和部署状态；
- 主动/被动声纳能力和水声通信半径；
- 所属 group、分段、角色和从脑状态；
- 当前声纳模式、局部方案版本和主脑连通状态。

### 5.4 `SubmarineTruthState`

关键字段：位置、航向、速度、加速度、最大转向率、巡航/冲刺速度、速度相关声学特征、任务水域、候选逃逸水域和已提交逃逸方案。

该对象仅存在于仿真与评估层。面向我方的对象始终是 `TargetBelief`。

## 6. 显式配置

所有默认兵力和关键参数必须在 `configs/` 中显式声明，禁止代码静默补齐平台数量或关键能力。

- `configs/environment.yaml`：地图边界、母舰、4 艘 USV、12 艘 UUV、单目标、初始位置、任务水域和逃逸水域。
- `configs/platforms.yaml`：各平台运动、能源、保障、投放和回收能力。
- `configs/sensors.yaml`：主动/被动及多基地观测参数。
- `configs/communications.yaml`：母舰-USV、USV-USV、USV-UUV 和 UUV-UUV 距离门限。
- `configs/doctrine.yaml`：空间分段、编组、预置、交接、轮转、主动发射和人工审批规则。
- `configs/llm.yaml`：主脑、从脑和敌方脑三个独立角色的模型、温度、超时、重连和 prompt 版本。
- `configs/acceptance.yaml`：量化验收阈值。

所有文件由 strict Pydantic 模型校验。未知字段、重复平台 ID、能力缺失、无效半径、不可回收编组和无法映射的 LLM 角色在启动时直接拒绝。

## 7. 距离通信图

通信只建模“连通/断开”，每个仿真周期按位置和配置门限重建图：

- 母舰与 USV、USV 与 USV 形成水面 mesh。
- USV 与 UUV、UUV 与 UUV 形成局部水下链路。
- 若母舰到 group 主 UUV 存在路径，则该从脑与主脑连通。
- 若路径不存在，从脑继续执行最后批准 doctrine 内的局部决策，主脑不能假定实时控制。
- 恢复连通后同步 belief 摘要、方案版本和执行状态；过期命令不得重放。
- 任一 USV 超出母舰保障半径均是硬约束违规，规划候选不得提交。

本阶段不模拟链路带宽、时延和丢包。

## 8. 协同多基地声纳

被动声纳默认持续开启。主动观测由一个受控发射节点和多个接收节点组成：

- 发射节点可以是具备主动能力的 USV 或 UUV。
- 当前连通且处于有效几何位置的平台可以成为接收节点。
- 默认优先考虑适合的 USV 发射，由 USV/UUV 共同接收；只有信息收益需要时才选择 UUV 发射。
- 不允许多个平台无序同时发射。

传感器能力至少包含：

- 被动探测范围、方位方差和 SNR 模型；
- 主动发射范围、主动接收范围和测量方差；
- 主动杂波敏感度；
- 发射冷却和能耗；
- 主动发射造成的声学暴露代价。

从脑的确定性边界根据被动 SNR、协方差趋势、失联时长、定位几何、主动杂波、预期信息增益、能力、能量、冷却、分段阶段和主脑约束，计算允许的动作集合。LLM 必须从允许集合中选择，独立校验器负责拒绝越界输出。

主动观测恢复稳定航迹后，时间受限的主动命令结束并回到被动。该关闭行为属于已批准命令的终止条件，不是规则策略接管。

## 9. 空间分段与动态编组

母舰主脑的战略链路为：

`态势汇总 -> 目标意图识别 -> 轨迹走廊预测 -> 空间分段 -> 动态编组 -> 截获与交接计划 -> 硬约束校验 -> 人工确认 -> 执行`

### 9.1 `TrackSegment`

每个分段包含：

- 空间边界和预测走廊范围；
- 预计进入/离开时间；
- 截获区和交接区；
- 最低跟踪质量；
- 指定混合 group 和备用资源；
- 前驱/后继分段；
- 失效条件和当前执行状态。

分段依据目标航向变化、平台到达时间、母舰保障范围和通信覆盖确定，不按预测时域机械等分。

### 9.2 `TrackingTaskGroup`

每个 group 同时包含 USV surface cell 和 UUV underwater cell。主脑根据以下条件动态编组：

- 传感器能力和观测几何；
- 平台当前位置和到达截获区时间；
- 转场、跟踪、交接和返航所需能源；
- USV 母舰保障半径；
- group 到主脑的预期连通路径；
- 后续分段和应急替换所需的资源保留。

group 主 UUV 由在位 UUV 中数值 ID 最大者承担。数值 ID 使用显式 `platform_index` 或自然数解析，禁止使用会把 `UUV-9` 排在 `UUV-10` 之后的字符串字典序。

### 9.3 执行状态机

`FORMING -> TRANSIT -> STAGED -> TRACKING -> HANDOFF -> RELEASED -> RETURNING`

下一 group 必须在目标预计到达前进入 `STAGED`。目标进入交接区后，新旧两组重叠观测并融合 belief；只有当新组质量稳定越过门槛，身份、航向和协方差一致时才完成交接。旧组在交接成功前不得提前释放。

### 9.4 `RelayTrackingPlan`

预定作战方案与轮转统一为一个版本化对象，至少包含：

- 目标任务和预测引用；
- 分段序列和 group 分配；
- 投放、预置、交接、释放和回收时序；
- 每组最低质量、声纳授权范围和通信要求；
- 备用资源、应急动作和失效条件；
- 人工约束、证据、版本和差异摘要。

目标偏航、通信断开、能源不足或交接失败会使受影响的未来分段失效，并触发新的待审批方案版本。

## 10. 母舰主脑 LangGraph

`CarrierMasterGraph` 按场景持久化，核心节点为：

1. 事件归并；
2. 全局 belief 更新；
3. 意图识别；
4. 轨迹预测；
5. 空间分段构想；
6. 主脑 LLM 战略建议；
7. 确定性编组和截获求解；
8. 独立方案校验；
9. 人工预览；
10. 版本提交和广播。

主脑 LLM 不输出最终成员或任意航路坐标，而是输出目标区域、分段偏好、质量要求、资源姿态、风险偏好和可释放软约束。确定性服务生成候选成员、截获点和可执行航路。

等待人工确认期间整个态势流和当前有效方案继续运行。只有确认后的方案才可提交；基于过期快照、违反保障半径或无法按时截获的方案必须拒绝。

## 11. Group 从脑 LangGraph

每个混合 group 拥有独立线程：

`局部观测融合 -> 质量/交接阶段评估 -> 声纳决策边界 -> 从脑 LLM 即时决策 -> 独立校验 -> 模式/队形/交接命令 -> GroupReport`

从脑在已批准 doctrine 和当前分段内可以：

- 选择协同主动发射和接收节点；
- 设置主动持续时间和退出条件；
- 调整局部观测队形；
- 执行预置、交接和释放动作；
- 在目标即将丢失时执行批准范围内的应急保跟踪动作，并上报追认。

从脑不得重写全局分段、跨组抢占资源或扩大主脑批准的主动发射边界。

## 12. 提示词和结构化决策

### 12.1 主脑提示词

必须显式包含：

- 当前作战规则和人工约束；
- 目标 belief、意图假设、预测走廊和信息新鲜度；
- USV/UUV 能力、位置、能源和部署状态；
- 母舰保障范围和当前通信图摘要；
- 当前方案、分段执行状态、交接风险和资源保留；
- 所有硬约束和可释放软约束。

### 12.2 从脑提示词

必须显式包含：

- 局部目标 belief 和质量趋势；
- 被动 SNR、多平台几何和最近观测；
- 主动杂波、信息增益、冷却、能耗和暴露代价；
- 当前分段、交接阶段、主脑授权和通信状态；
- 可选发射/接收节点的能力矩阵。

### 12.3 敌方提示词

必须显式包含：

- 敌方自身任务水域和候选逃逸水域；
- 可观测主动脉冲和概率性平台接触；
- `EnemyBeliefState`、跟踪压力和信息新鲜度；
- 自身运动能力、速度相关暴露和当前航迹；
- 已批准的逃逸构想类型和硬运动学约束。

三个提示词都必须明确禁止读取 truth、虚构平台、绕过硬约束和输出 schema 外字段。每次调用记录角色、模型、prompt 版本、输入哈希、结构化输出、校验结果和重连状态。

## 13. 敌方潜艇脑与博弈

### 13.1 敌方认知

潜艇只能感知：

- 主动脉冲来向、粗略距离和发生时间；
- 以概率方式探测到的附近平台噪声；
- 配置中的自身任务水域和逃逸水域。

它不得读取我方真实平台位置、真实编组、主脑方案或我方 belief。

### 13.2 `AdversaryGraph`

由主动脉冲、跟踪压力升高、航路受阻、接近任务区和周期复盘触发：

`敌方观测 -> belief 更新 -> 威胁评估 -> 敌方 LLM 逃逸构想 -> 候选航迹生成 -> 运动学/边界校验 -> 方案提交`

敌方 LLM 输出 `EvasionStrategy`：目的区域、机动类型、速度姿态、风险偏好、触发条件和证据。它不输出逐点航迹。

确定性编译器从静默转向、冲刺脱离、航向反转、绕行威胁区和继续任务等运动模板生成候选航迹，并仅在 LLM 已选择的构想内求解可执行参数。

### 13.3 双方时序隔离

每个周期固定顺序：

1. 推进真实状态；
2. 分别生成双方可见观测；
3. 双方只用各自观测更新 belief；
4. 触发对应 LangGraph；
5. 校验后的命令从下一周期生效。

该顺序避免任何一方读取另一方同周期尚未执行的决策。

## 14. 人在环路

以下战略变化必须人工确认：

- 新作战方案；
- 重新分段；
- 大规模编组变化；
- 母舰投放和回收计划；
- 超出既有 doctrine 的主动探测策略。

从脑在已批准范围内可自动切换主被动声纳、调整局部队形和执行交接。目标即将丢失时可先执行批准范围内的应急动作，再向主脑和操作员追认。

审批使用非阻塞的“预览 -> 确认/拒绝 -> 下一轮提交”流程。等待审批不暂停当前有效方案。

## 15. 真实 LLM 故障语义

真实 LLM 是在线算法核心，不提供规则替代路径。

任一关键主脑、从脑或敌方脑调用因超时、网络、限流、服务端错误或无效响应失败时：

1. 立即暂停整个仿真时钟；
2. 冻结平台、目标、传感器和计划状态；
3. 保留失败调用、checkpoint 和输入证据；
4. 按角色配置持续重连并重新执行同一逻辑调用；
5. 成功获得并校验真实 LLM 输出后，从同一仿真时刻恢复；
6. 只有操作员可以中止等待并将本次场景标记为失败。

mock 输出、规则策略和确定性应急构想不得解除暂停。确定性校验器仍可拒绝无效 LLM 输出；被拒绝后继续内容修复或重连，仿真保持暂停。

## 16. UI 信息架构

UI 参考 `Maritime-Surveillance` 的顶栏、Canvas 主地图、固定右侧栏、可调整底部抽屉和回放栏布局，但替换全部 UAV 海上搜索业务语义。

### 16.1 Canvas 图层

1. 场景背景图、坐标网格和任务/逃逸水域；
2. 母舰和保障半径；
3. USV 水面 mesh、连通状态和主动发射范围；
4. UUV、group 颜色、从脑标识、声纳模式和轨迹；
5. 目标 belief、协方差和受控 evaluation truth；
6. 预测走廊、空间分段、截获区和交接区；
7. 当前、预置、交接和返航 group 航路；
8. 主动发射节点、接收节点和观测关系。

界面使用现有背景、母舰、UUV 和潜艇位图，并增加专用 USV 位图，不使用同一资产冒充不同平台。

### 16.2 顶栏和右侧栏

顶栏提供直播/回放、连接状态、仿真暂停原因、方案审批提示、图层和轨迹控制。右侧栏展示任务时间、方案版本、跟踪质量、通信连通率、母舰投放回收状态、混合 group 清单、平台能力和三个脑的连接状态。

### 16.3 底部抽屉

- `方案审批`：新旧分段、编组和航路差异及确认操作；
- `分段任务`：状态、预计到达、group、交接门槛和失效原因；
- `事件时间线`：逃逸、重规划、声纳切换、断联、交接和回收；
- `LLM 审计`：主脑、从脑和敌方脑输入摘要、输出、校验、修复和重连；
- `指标/参数`：跟踪、交接、主动占空比和只读配置；
- `回放`：事件跳转、播放、暂停、调速和逐帧查看。

战略方案采用地图差异预览和结构化抽屉审批。等待确认时当前态势持续刷新。

## 17. 迁移策略

采用新增契约和兼容适配器逐层替换：

1. 冻结现有可运行基线和测试结果；
2. 保留当前未提交旧算法补丁并单独审查，不覆盖或删除；
3. 新增平台、通信、belief 和方案契约；
4. 用适配器把旧 `SituationSnapshot` 和 UI frame 映射到新读模型；
5. 依次迁移仿真、group、主脑、敌方脑、API 和 UI；
6. 所有消费者迁移且回归通过后才移除旧契约。

旧补丁中可复用的能力、质量和轮转测试迁移到新模型；旧的多目标分配和按时间均分分段不作为新架构约束。

## 18. 错误处理与一致性

- 配置错误：启动失败并报告具体字段。
- LLM 不可用或输出无效：按第 15 节暂停整个仿真并重连。
- 方案版本过期：拒绝提交，保留当前方案。
- 通信断开：从脑在最后批准 doctrine 内自治，主脑标记信息陈旧。
- 主 UUV 失效：按数值 ID 立即重选；无有效 UUV 时 group 失效并产生战略事件。
- 交接失败：保持旧组、延长重叠观测并请求新的从脑/主脑决策，不提前释放资源。
- 硬约束不可满足：候选方案不可进入人工确认。
- truth 泄漏：契约校验和测试直接失败，不写入 operational ledger。
- 重复命令：使用 command ID、方案版本和执行回执保证幂等。

## 19. 测试与验收

### 19.1 单元测试

- 二维运动学连续性和速度/转向约束；
- 母舰保障半径和投放回收状态机；
- 距离通信图及多跳连通；
- USV/UUV 能力判定；
- 多基地发射/接收观测；
- belief 真值隔离；
- 空间分段、截获点和动态编组；
- leader 选举和交接状态机。

### 19.2 Graph 测试

- 主脑、从脑和敌方脑结构化输出；
- prompt 决策因素覆盖；
- schema/语义修复；
- checkpoint、版本和信息新鲜度；
- 人工预览/确认；
- LLM 失败暂停和真实重连恢复；
- 禁止规则或 mock 在线接管。

### 19.3 端到端仿真

默认场景至少完成：

- 三个空间分段；
- 两次重叠交接；
- 一次潜艇主动逃逸；
- 一次通信断开和恢复；
- 一次目标偏航后的重新分段；
- 一轮人工方案确认；
- 主脑、至少一个从脑和敌方脑的真实 LLM 有效调用。

### 19.4 UI 验收

- Vitest 和 production build；
- Playwright 覆盖直播、回放、平台选择、方案审批和 LLM 暂停/恢复；
- 1440x900、1366x768 和移动窄屏截图；
- Canvas 像素检查确保背景、平台、分段、通信和声纳图层非空且不重叠。

### 19.5 量化指标

`configs/acceptance.yaml` 至少包含：

- 连续跟踪率；
- 交接中断时长；
- 重捕时间；
- 主动声纳占空比；
- 通信连通率；
- 资源轮转完成率；
- 敌方逃逸成功率；
- 真实 LLM 调用和有效决策覆盖率。

安全门槛固定。传感器相关质量阈值通过固定随机种子的 pilot 运行校准并冻结，正式运行不得动态降低验收标准。

## 20. 完成定义

只有同时满足以下条件才可宣称总体重构完成：

- 四个子项目规格和实施计划均完成；
- 默认显式配置可启动并运行；
- 主脑、从脑和敌方脑真实 LLM 路径全部工作；
- 分段、预置、重叠交接、轮转和重新分段在运行中可观察；
- 人工审批能够改变下一版方案且不阻塞当前方案；
- LLM 失败会暂停仿真并在真实重连后恢复；
- operational 路径无 truth 泄漏；
- Python、类型检查、前端、Playwright 和端到端验收全部通过；
- UI 使用指定资源并符合参考项目的信息架构。
